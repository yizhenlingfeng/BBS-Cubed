### 2. 整理目标

1. 删除经过调用关系、Mixin、反射和序列化交叉确认的无用代码。
2. 合并重复 Accessor、重复 Mixin 和版本间重复业务逻辑。
3. 拆分超大类，建立清晰的数据层、业务层、UI 层和版本适配层。
4. 保持 1.20.1、1.20.4、1.21.11 行为兼容。
5. 保持旧影片、模型、关键帧、设置文件和第三方插件兼容。
6. 统一新代码的命名、日志、异常处理和注释风格。
7. 每个阶段独立提交、独立验证，避免一次性全项目重排。

### 3. 明确不做的事情

- 不根据“类名没有出现在其他 Java 文件里”单独判定死代码。
- 不大规模重命名 `bbspp`、`bbsppp`、`bbspp_cml` 等持久化或 Mixin 标识。
- 不为了合并而合并两套语义不同的渲染管线。
- 不删除仍在使用的旧存档迁移和旧插件兼容代码。
- 不引入与现有 Allman 括号风格冲突的全项目格式化工具。
- 不顺手修复与整理无关的功能问题。
- 不将 `libs/` 上游参考源码与主源码一起重构。
- 不把重构、格式化、功能修改和无关缺陷修复混入同一个提交。

### 阶段 C：多版本代码去重

统一采用以下结构：

```text

src/main/java-1.20.x/             1.20.x API 适配
src/main/java-1.21.11/            1.21.11 API 适配
```

版本适配层只处理：

- 类包路径变化；

#### C-07 分类清单（2026-11-25）

两版同名文件共 31 组，其中 C-01~C-06 已共享 3 组（`ParticleComponentParticleMorph`、`ParticleComponentCollisionAppearance`、`ParticleComponentCollisionTinting`），另有 4 组（`ItemSprayCameraAdapter`、`ItemSprayWorldRenderHook`、`CategoryIconMatrix`、`GameModeAdapter`）是**有意的版本侧适配器**，本来就应当保留两份。剩余 24 组的分类结论如下。

判据：

- **可共享**：差异只有单一 API 改名或包路径移动，业务逻辑逐字相同。上提后版本侧只留调用适配。
- **只能部分共享**：纯数学、数据结构、参数解析可以上提；渲染状态管理与提交方式必须留在版本侧。
- **必须独立**：渲染管线语义不同、上游生命周期不同，或功能在一侧尚不存在。

## 五、死代码判定与删除流程

所有删除候选必须经过以下流程：

| 步骤 | 检查内容 | 不能忽略的情况 |
| --- | --- | --- |
| 1 | Java 直接调用、继承、字段和方法引用 | 同名类、内部类、Lambda、方法引用 |
| 2 | `fabric.mod.json` 和全部 Mixin 配置 | 入口类、Accessor、Invoker、Mixin Plugin |
| 3 | `Class.forName`、反射方法名字符串、动态代理 | 可选功能和版本适配类 |
| 4 | 序列化键、数据迁移和资源路径 | 类名可能不参与存档，但键名必须稳定 |
| 5 | 测试发现和命令注册 | JUnit 测试类没有普通调用方是正常的 |
| 6 | 空方法和空捕获 | 可能是接口要求或有意的兼容降级 |
| 7 | 双版本引用 | 一个版本未使用不代表另一个版本无用 |
| 8 | 游戏内验证 | Mixin 是否实际 apply、可选功能是否正确降级 |

删除策略：

- **直接删除：**合并后重复文件、无用导入、已确认无引用的私有成员。
- **测试后删除：**空覆盖、工具方法、调试辅助、旧兼容分支。
- **暂不删除：**旧数据迁移、Mixin 兼容层、资源翻译键、外部插件适配。
- **不自动删除：**语言 JSON 中搜索不到的键，因为大量键通过字符串拼接动态生成。

明确保留的兼容代码包括：

- `src/main/java/gbeic/bbsplusplus/keyframes/LegacyTextureTweenTrackMigration.java`：仍有实际旧轨道迁移调用。
- `src/main/java-1.20.x/gbeic/bbsplusplus/client/morph/LegacyMorphMapping.java`：仍承担旧 Morph 数据兼容。
- `src/main/java/gbeic/bbsplusplus/mixin/irlite/LegacyIRLiteBbsCasterSourceMixin.java`：仍承担旧版 IRLite 目标兼容。

## 八、风险与回退策略

| 风险 | 影响 | 控制措施 | 回退方式 |
| --- | --- | --- | --- |
| Accessor 合并后接口未注入 | 音频、小窗、锁定或流体功能异常 | 保留已注册实现和注入方法名，逐组验证 | 回退对应功能域提交 |
| 多目标 Mixin 行为不一致 | 三类轨道重置失效 | 先运行时验证，不稳定则使用三个薄壳 | 恢复三个独立 Mixin |
| 共享层引入版本专属类 | 另一版本编译或类加载失败 | 共享层只做版本中立逻辑，双构建和启动检查 | 回退该版本适配提交 |
| Pose 数据拆分改变序列化 | 旧影片数据丢失或插值变化 | 固定键名，增加 round-trip、copy、equals、hashCode、lerp 测试 | 恢复编解码或插值辅助层，不改数据格式 |
| 渲染拆分改变状态或顺序 | 黑屏、深度、透明度或性能回归 | 小步移动，不重写算法；保留原调用顺序 | 回退对应渲染拆分提交 |
| 构建脚本整理改变产物 | Mixin 或 shader 缺失、资源串版本 | 双顺序构建、检查 jar、class-diff 和资源清单 | 回退构建提交，源码整理可继续 |
| 全量格式化产生海量差异 | 无法审查、掩盖行为变化 | 仅格式化触碰文件，风格与功能提交分离 | 丢弃纯格式化提交 |
| 误删兼容代码 | 旧数据或旧插件失效 | 明确保留 Legacy 代码，执行旧数据验证 | 恢复删除文件和加载入口 |
| 上游可选模组或关闭流程异常 | 冒烟结果受模组组合影响，退出 watchdog 复现 | 保留最小组合日志，逐一加入可选依赖，记录游戏与模组版本 | 用同一存档副本回到上一套已验证的组合，确认问题随哪一项变化后定位 |
| 存档对照样本串用 | 两个构建读取到不同数据或覆盖原档 | 固定样本哈希，按版本与产物分别复制 | 从原始样本重新复制并复测对应场景 |
