**B2 实施偏差（2026-11-11）**：
- **B2-01 拆的是提交点，不是 `GradePass` 的 draw command**。1.21.11 的 `ModelInstance#render` 是「每个材质通道一个 `BufferBuilder` → 一次 `FormTranslucentQueue.submit`」，贴图/深度/剔除都被固化在那条提交所用的 `RenderLayer` 上，所以逐骨骼特性必须先拆提交。实现为 `@Redirect` 拦 `CubicRenderer.processRenderModel`：`ModelGroupSubmit121.split(...)` 为每个顶层组各建一个 `BufferBuilder`、各 `finish` 一次焊接补丁、各提交一次；遍历顺序与组内顶点顺序与上游逐行一致，只增加 draw call、不改合成顺序。
- **两阶段是必须的**：颜色叠加走 `FormOverlay` 调色板（每骨骼一个纹素、顶点用 UV2 寻址、整张表在遍历结束后才上传），边遍历边提交会让先提交的组采样到还没填完的调色板。`split` 先把所有组缓冲造完，再一次性交给调用方上传调色板并逐组提交。
- **B2-02/B2-03 复用了 `FormPbr.resolveAlbedo` 与 `IrisUtils`/`BBSRendering.trackPbrVariant`，没有给 `GradeParams`/`GradePass` 加每组 UBO**。逐骨骼 PBR 在 1.21.11 的正确形态是「每骨骼一张变体贴图」（`getVariant(link, "pbr_bone:<material>:<identityHashCode(form)>:<5 个 0-255 值>")`），因为 PBR 参数的消费方是 Iris 的 entity 管线，而不是我们的 grade UBO。为此新增 `BoneMaterialContext121`（`ThreadLocal`）把 `ModelFormRenderer#albedo(String, Link)` 的形参记下来 —— 逐组提交需要这个 `Link` 才能造变体，而它只存在于那个方法的局部变量里（`mixin12111/ModelFormRendererAlbedoMixin121` 在 HEAD 记录）。
- **B2-04 映射到 `ModelVariant.cull`，不是索引范围**。`BoneGroupResolve121.culled(instance, baseCull, group)` 读 `LimbCullingConfigHolder.bbspp$getLimbCullingBones()`，命中该组 id 的组走 culled 变体；其余沿用 `instance.isCulling()`。组本身的 `isVisible()` 由 `walk` 判断，隐藏组直接不提交。
- **B2-06 的「逐组 glint」靠新增 `ModelGradeResolver.resolveForGroup(instance, group)`**：原 `resolve(ModelInstance)` 只能取第一个开了光效的组，会导致整模型发光；逐组版只取这一组自己的 `GroupGlintHolder`（全 0 回落 `group.current instanceof GlintHolder`），调色/白化仍是整表单级。
- **B2-07 的消费方变了**：1.20 的 `OutlineRenderer120.renderLabPBR` 用 `RenderSystem.setShader(entityTranslucent) + setShaderTexture` 逐批换贴图；1.21.11 换成「每张生成的伴生贴图一个 `RenderLayer`」（自建 `pipeline/outline_glow`：`ENTITY_EMISSIVE_SNIPPET` + `withDepthWrite(false)` + `withCull(true)`，`RenderSetup.texture("Sampler0", id)`，按 identifier 缓存在 `GLOW_LAYERS`；**不要**换回 `RenderPipelines.ENTITY_TRANSLUCENT`，它写深度会把模型本体挡掉）。为此给 `OutlineEmissiveTexture` 加了 `diffuseIdentifier(argb, glow)` / `gradientIdentifier(gradient, glow)`，让渲染器拿得到 Iris 认识的那个 identifier。
- **⑨ B2-07 与任务原文的偏差（2026-11-12 修订）**：外壳的发光强度**只取轮廓自己的 glow 滑条**（`spec.glow()`），PBR 的 `GroupPbrHolder.bbspp_cml$getEmission()` **不再**参与画壳。原因：外壳用的是生成的「轮廓色 1×1 贴图」，不是模型贴图，只设 emission、不设轮廓色的骨骼会被默认白色外壳整根盖白（实机回归）。PBR emission 改走 LabPBR 正规通道 —— `BoneGroupResolve121.resolveBonePbr` 的五值经 `BBSRendering.trackPbrVariant` 进 `IrisUtils`，Iris 按该骨骼 albedo 着色发光，颜色正确且不遮盖。
- **B2-08 提供了对拍开关而不是硬编码阈值**：`-Dbbspp.debug_per_bone_stats` 每秒打一行 `ModelGroupStats121` 统计（模型数/拆分·回退数/提交次数/单模型最多组数/开关状态），把这个参数的有无各跑 30 秒即可对比 draw call 与帧时间。降级线是 `ModelGroupSubmit121.MAX_GROUPS = 96`（超限回退整模型）、`-Dbbspp.disable_per_bone_split`（整体关闭）、以及拆分抛异常后 `broken = true` 的永久回退。

5. **「描边开启自发光后同样发白」（2026-11-12 01:45 修复，与第 4 条同源但更深一层）**：自发光壳直接复用了 `RenderPipelines.ENTITY_TRANSLUCENT`，而它的构建是「**写深度 + 不剔除**」（javap 实证：`withCull(false)`，未调 `withDepthWrite(false)`）。壳在模型本体**之前**绘制，写深度后本体在 LEQUAL 下被挡掉，整根骨骼只剩壳的轮廓色（默认白）→ 发白；不剔除又让内外两面各画一遍，alpha 叠成接近不透明。1.20 的对应做法是显式 `depthMask(false)` + `enableCull()`。现改为自建管线：`ENTITY_EMISSIVE_SNIPPET`（经 access widener 暴露，`gradle/outline-1.21.11.accesswidener`）+ `withDepthWrite(false)` + `withCull(true)` + `withSampler("Sampler1")`，并用 `BBSRendering.mirrorIrisPipeline(pipeline, RenderPipelines.ENTITY_TRANSLUCENT_EMISSIVE)` 让 Iris 把它认成 entity emissive 程序（emission 只在 entity 程序里生效，同时消掉 `Missing program bbsplusplus:pipeline/outline_glow` 这类 override 警告）。

⑤ **粒子预览的「红色大块」是上游坐标轴错位，用 mixin 修正（2026-11-13 实机回归）。** 现象：打开粒子编辑器预览，视口里出现一块铺满画面的纯红矩形（`RGB 255,64,89` = `Colors.RED = 0xff4059`），粒子本身画得对。根因在上游 `libs/bbs-fs-1.21.11/src/client/java/mchorse/bbs_mod/ui/particles/UIParticleSchemeRenderer.java:216-219`（`renderGrid`）：画 `Draw.coolerAxes` 前用的是
```java
MatrixStack stack = new MatrixStack();
stack.multiplyPositionMatrix(new Matrix4f(InverseView.get()).invert());
```
而 `InverseView` 只装了 `camera.view` 的 **3x3 部分**（`Camera.updateView()` 只做三次 rotate，平移在独立的 `camera.position` 里，见 `libs/bbs-fs-1.21.11/src/main/java/mchorse/bbs_mod/camera/Camera.java:84-90`），所以这里得到的是**纯旋转 `R`**，缺了 `T(-camera.position)`。坐标轴是唯一「用世界坐标直接喂矩阵」的几何（粒子不是——`ParticleEmitter#render` 自己先减了 `cX/cY/cZ`，所以粒子看着正常）。结果 X 轴那根 2 格长的实心盒子的一个面正好落在透镜原点附近（`fillBox(0, -o, -o → size, o, o)` 的 `x1=0` 面距眼约 `axisOffset`），在近裁剪面上铺满视口；绿色/蓝色盒子的「贴眼面」是穿过眼点的平面（退化）、白色盒子把眼点包在里面（被近裁剪面裁掉），**所以只剩红色**——颜色与几何都对得上。修法：新增 `src/main/java-1.21.11/gbeic/bbsplusplus/mixin12111/UIParticleSchemeRendererMixin121.java`，`@Redirect` 掉 `renderGrid` 里那一次 `Draw.coolerAxes`，改用与同一面板地面网格同源的 `camera.view * T(-camera.position)`（等价于 `UIModelRenderer.createCameraStack()`，普通预览下 `transform` 是单位矩阵故不重复乘）。**不去改 `libs/`**（该目录不在版本控制内，补丁无法提交、也无法被 `build.gradle` 的排除表覆盖）。粒子侧的 `renderUserModel` 保持上游原样——它当前的 `InverseView` 用法配合 `ParticleEmitter#render` 内部的相机平移是对的，换成完整相机栈反而会让粒子整体偏移一个摄像机位置。

## 4. 单任务施工规范

### 4.1 分支与提交

- 分支：从 `3.5` 切 `feat/12111-<batch>`；每批一个 PR/合并点。
- 提交：一个任务一个 commit；B0-01+B0-02 可合并为“恢复构建”。
- 提交信息：`feat(1.21.11/model): port extruded UV (B1-01)`；`fix(1.21.11/build): ...`。
- 每个 commit 附：双构建结果、冒烟场景、回退方式。

### 4.2 Mixin 规范

- 1.21.11 专用 mixin 放 `gbeic.bbsplusplus.mixin12111`，配置 `bbsplusplus-12111.mixins.json`。
- 方法前缀统一 `bbspp$`；`@Inject`/`@Redirect` 尽量 `require = 0`，启动自检记录。
- 不修改 1.20.1 已存在 mixin 的注入点；需要分叉时复制到 `java-1.21.11`。
- 目标类已删除的旧 mixin（`CubicVAORendererMixin` 等）**不解除排除**，重写新类。

### 4.3 渲染规范

- 模型/半透明：继续走 `FormTranslucentQueue.DrawCommand`；`flush()` 在帧末、pass 之外，`draw()` 内开 pass 合法。
- 自定义 uniform：`RenderPipeline` + std140 UBO + `RenderPass.setUniform`；不要找 `GlUniform` setter。
- 屏幕后处理：`PostEffectPipeline`/`PostEffectProcessor`；必须带 `ScreenQuadPass` fallback。
- 原版粒子：`ParticleManager.addToBatch`，颜色字段在 `BillboardParticle`。
- Iris 世界变体：`BBSRendering.mirrorIrisPipeline(...)`；shaderpack 覆盖时允许降级。

### 4.4 数据规范

- 不改 `bbspp_*` NBT 键名；新增字段用可选读，缺省不报错。
- Particle Plus/AAA 旧方案只读兼容；保存前检测未知组件并提示。
- 发光方块缺失时退化为空气/未知，不阻断区块加载。
