# BBS-Cubed 1.21.11 未移植内容清单

> 基线：3.6.5 源码（工作区当前状态）+ `build/1.20.1`、`build/1.21.11` 两个构建产物。
> 核对方式：`build.gradle` 的版本排除表、两个 jar 的 class 清单、1.21.11 专用源码目录、运行期反射守卫，以及每个被排除 mixin 的注入点。
> 一句话结论：1.21.11 不是“全功能版”，而是“1.20.x 主体 + 82 个源文件被排除 + 11 个 1.21.11 专用文件”的实验构建；大多数“没生效”不是 bug，而是整条实现链路根本没进 jar。

**阅读指引**：只想知道“缺什么”看第 1、2 节；想知道“README 写的功能到底怎样”看第 6 节；查某个设置项看附录 C；评估依赖/装插件看第 7 节；排查“开关没反应但没报错”看第 8 节；移植后验收看第 9 节。

## 1. 未移植功能（按模块）

### A. 渲染管线：模型 shader 扩展与屏幕后处理

1.21.5+ 的 GPU 渲染管线大修后，1.21.11 构建排除了所有引用旧立即模式 API 的渲染文件（`build.gradle:275-279` 注释：`RenderSystem.enableBlend`、`Tessellator.getBuffer`、`ShaderProgram`、`GlUniform`、`AbstractTexture`、`BufferRenderer`、`WorldRenderEvents` 等，待按 `RenderPipeline`/`RenderLayer` 逐文件重写）。1.21.11 的模型 shader 也被换成了 36 行的原版格式 `model.vsh`（只有 `Position/Color/UV0/UV1/UV2/Normal`），没有 BBS++ 的任何 uniform。

| # | 功能 | 1.21.11 用户可见表现 | 被排除的实现 |

| A1 | 附魔光效（Glint） | 模型/姿势里的附魔光效强度、颜色、相位完全不显示；编辑器控件仍可调 | `client/glint/GlintRenderer`（只有 1.20 版）、`ModelTextureGradeShader.applyGlint`、`mixin/client/CubicVAORendererMixin`、`mixin/ModelVAOMixin` 的 glint VAO 路径 |

补充：

- **A8 的数据层还在**：`ColorClip.getEffects(context)` 仍从 `context.clipData` 的 `bbspp_colorEffects` 取效果，`ColorClip`/`CinematicClip` 仍会写入；只是全仓库唯一的消费端 `ScreenEffectRenderer` 不在 jar 里。
- **A9 的剪辑类型仍注册**：`HotbarClip` 与 `UIHotbarClip` 都在，`HotbarClip.getHotbars` 仍能拿到数据；缺的只是渲染。
- **A8/A9 的注入点细节**：`BBSRenderingMixin` 在 `BBSRendering#onWorldRenderEnd` 的 `RETURN` 处只服务三类画面——`/play` 的 `PlayCameraController`、录制中的 `CameraWorkCameraController`、以及编辑器预览（`BBSRendering.isCustomSize()` + `UIFilmPanel` 非空）。它把投影切成 `new Matrix4f().ortho(0, w, h, 0, -1000, 3000)`，再调用 `UIHotbarRenderer.renderHotbars` 与 `ScreenEffectRenderer.render`，最后恢复投影/深度。所以 1.21.11 丢的不只是“世界播放时”的 HUD/后处理，编辑器里“调完立即看到”的预览也一起没有。
- **A1/A2/A4/A5 的共同点**：`ModelMixin`/`ModelGroupMixin`/`PoseTransformMixin` 仍在，所以数据、插值、UI 都正常；断的是“从 group 到 draw call”的消费端。
- **A12 是已知缩水，不是漏移植**：1.21.11 的描边实现是另一套（`OutlineRenderer121`），只保证纯色+深度。
- **A12 的辉光回退**：`OutlineRenderer121.java:38-43` 注释说明 1.21.5 移除了 `RenderSystem.setShader`/`BufferRenderer`，改用 colour（depth test、不写深度）+ depth-only 两个不可变 `RenderLayer`；`glow groups` 在 1.21.11 LabPBR entity layer 移植前直接回退纯色，不会报错。
- **A12 的世界实体层序差异**：`ModelInstanceOutlineMixin121.java:27-35` 注释说明世界实体经 `FormTranslucentQueue` 延迟；队列活跃时颜色 pass（HEAD）在帧末 body flush 之前、仅深度 pass（RETURN）也在 flush 之前，而 UI 预览/立即路径仍严格保持 Cool_pack 顺序。可能表现为世界描边与实体的前后关系不正确，但 UI 预览和立即路径不受影响。

**F2 原来会做什么**：`UIShaderCurvePickerOverlayPanel` 的头注是“把 BBS 从 Iris 菜单整理出的本地化路径还原成『分类页 > 参数』层级，搜索仍覆盖全部参数”，并 import `SafeShaderLanguageMap`/`ShaderCurveState`/`IrisCompat`。1.21.11 回退成 BBS 原生的单层搜索列表，不是“曲线功能完全没了”。

**F3/F5/A7 的共同根因**：`BaseFilmControllerMixin` 是唯一同时负责 `VideoTimelineState.beginFilmRender/endFilmRender`、`WorldFilmShaderCurveState.sample`、`bbspp$sampleEquipmentTransforms` 的注入点；一个 mixin 被排除，同时导致世界播放曲线失效、视频寻帧退化、装备变换不应用。不要把它们当成三个独立 bug。

**F8 的编辑入口细节**：`UILinkKeyframeFactoryMixin` 在 `UILinkKeyframeFactory` 构造 TAIL 给模型原生纹理轨道追加“模式/像素块/扩散起点”控件，只有 `originControl` 被点击时才 `new UITextureTweenOrigin3DPicker(...)`；而 `TextureTweenManager` 的驱动 mixin 都未排除，所以是“老数据能播、新参数不能建/不能改”。

### H. 文档与实现漂移（顺带发现，不是 1.21.11 差异）

- `README.md:25` 的“第一人称视角晃动”在当前源码里找不到实现：`BBSPlusPlusSettings` 没有注册 `first_person_bobbing`，全仓库只有 `zh_cn.json`/`en_us.json` 的 lang key（`bbspp.config.bbs_enhancements.first_person_bobbing`）。所有版本都如此，建议单独核对 README。
- `README.md:24` 的“姿势骨骼树形列表”也是“文档比实现新”：`BBSPlusPlusSettings` 没有注册 `pose_bone_tree_view`，全仓库只有 lang key；而 BBS 2.7 本体已经自带树形骨骼列表——`libs/bbs-fs-2.7-1.20.1/.../ui/utils/pose/UIPoseBoneStringList.java:14` 与 `libs/bbs-fs-1.21.11/.../UIPoseBoneStringList.java:14` 都 `extends UIBoneTreeList`，`UIBoneList.java:49` 直接 `new UIPoseBoneStringList(...)`。也就是说树形列表是 BBS 原生、始终启用，不存在“开启后”的开关；1.21.11 上它反而正常可用，不要把它列为缺失。
- `README.md:45` 的“模型方块渲染距离”默认值写 0（原版 512），但 `BBSPlusPlusSettings.java:131` 注册的是 `builder.getInt("model_block_render_distance", 256, 0, 1024)`，默认 256。这是所有版本都存在的“文档默认值 vs 代码默认值”漂移：开箱即用会把模型方块渲染距离压到 256，而不是 README 说的原版默认值。

- `texture_manager_layout` 是隐藏项且无消费端，当前所有版本都是死设置。
- README:197-198 的“曲线崩溃/飞行模式曲线修复”和 README:203 的“颜色膨胀修复”在源码里没有可直接对应的独立实现：`ShaderCurvesMixin` 修的是光影曲线解析崩溃/性能，`ValueColorsMixin` 修的是颜色预设列表重复膨胀；这三项在第 6.4 节标为待确认，不要直接算成 1.21.11 缺失。
- `docs/BBS-Cubed_整理计划.md`（2026-10-30，基于 3.6.0）已经过时：写“98 条 excludes（97 唯一）”“`java-1.21.11` 只有 1 个文件”“1.21.11 mixin JSON 非法”“`FluidController` 是孤儿”，与现状（82 条、11 个文件、JSON 已修、`FluidController` 被 1.21.11 渲染器使用）不符；但“约 20% 功能静默缺失”的结论仍成立。

## 3. 1.21.11 已移植 / 仍可用

## 4. 建议的移植顺序（按投入产出）

1. **先加“不可用”提示/守卫**：1.21.11 上把 F1–F10 的设置项隐藏或标灰，至少避免用户以为坏了；`UIElementMixin` 的分类菜单删除逻辑加 `classExists(UIBBSPPFormList)` 守卫，避免 F1 的“菜单少三项”副作用。
2. **P0：屏幕后处理 + HUD**：`ScreenEffectRenderer`/`ColorGradeRenderer`/`BBSRenderingMixin`/`UIHotbarRenderer`。这是用户感知最强的整块功能（颜色剪辑、电影剪辑、快捷栏剪辑），且与模型 shader 相对独立。
3. **P0：模型 shader 扩展**：`ModelTextureGradeShader`（tint/white/glint/PBR 变体）、`CubicVAORendererMixin`、`ModelVAOMixin`、`ModelVAORendererMixin`、`ModelInstanceMixin`、`CubicCubeRendererUvEmitMixin`、`ExtrudedFormRendererMixin`、`BillboardFormRendererMixin`。需要按 1.21.5+ 的 `RenderPipeline`/`RenderLayer`/`GlUniform` 接口重写，工作量最大；可先做 tint/UV（不依赖 Iris），再补 glint/PBR。
4. **P1：粒子**：`ParticlePlusClient` 的组件注册和 Additive 材质可以先做（数据层不依赖渲染管线）；渲染用的 `ParticleEmitterMixin`/`ParticleComponentAppearanceBillboardMixin` 后补。AAA 需要 `aaa_particles` 的 1.21.11 版本。
5. **P1：纯 UI 类**（风险低、收益直接）：`UIBBSPP*` 新伪装界面、`UIShaderCurvePickerOverlayPanel`、`UIAnimationPreview*`、`PoseBoneMarkerRenderer`、`UIActionsConfigEditorMixin`、`UILinkKeyframeFactoryMixin`、`UITextureTweenOrigin3DPicker`、`UIParticleScheme*`。这些大多不碰渲染 API，可以优先合入。
6. **P2：mixin-only 小功能**：`FilmAutoGameModeRestoreState` 全链路、`MinecraftClientMixin` 的 IMBlocker/VFX 输入、`IRLiteBbsCasterSourceMixin`（物品喷射阴影）、`GameRendererMixin`+`VfxCoreShaderRegistrationGuard`（VFX 去重）。
7. **P2：方块**：`BBSPlusPlusBlocks` 改用 1.21.11 的方块注册 API（`FabricBlockSettings` 已移除），并考虑老存档的 registry 缺失处理。
8. **P2：世界播放**：`BaseFilmControllerMixin` 恢复 `VideoTimelineState`、`WorldFilmShaderCurveState`、装备变换采样；`WorldFilmControllerReplayTimeMixin` 恢复世界播放回放时间桥。
