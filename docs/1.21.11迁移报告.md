# BBS-Cubed 1.21.11 构建支持迁移报告

> 生成时间：2026-10-10
> 范围：仅做对比分析，**未对源码做任何修改**
> 目标：让 `./gradlew build -Pmc_version=1.21.11` 能编出一份 1.21.11 可用的 jar（功能完整性另论）

---

## 0. 一句话结论

本项目与 1.21.11 之间的距离，**不在 BBS addon API**（addon 表面与 1.20.1 几乎一致），而在三件事：

1. **构建链要整体抬到 Java 21 + Loom 1.15/1.16 + Loader 0.19.x**（机械改动，约 30 行 gradle）；
2. **MC 1.21.5 渲染管线大修**（`RenderSystem` / `GlStateManager` / `BufferBuilder` / `RenderLayer` 全部重写），命中本项目 **20 个文件、184 处调用**，这是工作量主体；
3. **BBS 自身删了 `CubicVAORenderer`**，本项目 2 个直接针对它的 Mixin 必须重写或废弃；
4. 可选依赖（AAA Particles、Iris、ForgeConfigAPIPort、Architectury、VFX、IRLite、Xavin、Together）在 1.21.11 上要么版本号要换，要么没有对应版本需要降级为 compileOnly。

## 2. 构建系统改动清单

### 2.1 `gradle.properties` 新增条目

在现有 `1.20.1` / `1.20.4` 段落后追加一段：

```properties
# ---- 各游戏版本依赖坐标（1.21.11）----
minecraft_version_1.21.11=1.21.11
yarn_mappings_1.21.11=1.21.11+build.6
fabric_api_version_1.21.11=0.141.4+1.21.11
loader_version_1.21.11=0.19.3
iris_version_1.21.11=1.10.7+1.21.11-fabric
# AAA Particles：1.21.11 上最新线是 26.1.x（chloeprime 跟随 Mojang 新命名），
# API 包名仍为 mod.chloeprime.aaaparticles.*，但具体小版本需在 Modrinth 实拉一次确认
aaa_particles_version_1.21.11=<待确认>
forgeconfigapiport_version_1.21.11=21.11.1
architectury_version_1.21.11=19.0.1
bbs_jar_1.21.11=libs/bbs-2.7-1.21.11.jar
```

**注意**：本项目当前 `loader_version=0.18.1` 是全局单值（用于 `modImplementation "net.fabricmc:fabric-loader:${loader_version}"`），但 BBS 1.21.11 要求 `>=0.19.3`。两种处理方式：

- **方案 A（推荐）**：把 loader 版本也收进 `versions[ver]` 字典（`loader_version = mcVer.loader_version`），让 1.20.1/1.20.4 继续用 0.18.x，1.21.11 用 0.19.3。
- 方案 B：全局抬到 0.19.3（向下兼容，因为 Loader 向后兼容旧 MC）。

### 2.2 `build.gradle` 改动

1. **`versions` 字典追加 `1.21.11` 条目**（结构完全仿 1.20.4），新增字段：
   - `loader_version: "0.19.3"`
   - `bbs_jar: gprop("bbs_jar_1.21.11")`
   - `aaa_as_compile_only: true`（1.21.11 上先按 compileOnly 跑通，后续再切 modImplementation）

2. **Java 版本切换必须按版本分支**（关键）：
   - 当前 L142–144 写死 `sourceCompatibility/targetCompatibility = "17"`。
   - 1.21.5+ MC 强制 Java 21。需要改成：
     ```groovy
     tasks.withType(JavaCompile).configureEach {
         it.options.encoding = 'UTF-8'
         if (targetMc == "1.21.11") {
             it.options.release = 21
         } else {
             it.sourceCompatibility = "17"
             it.targetCompatibility = "17"
             it.options.compilerArgs += ["-XDignore.symbol.file", "-Xlint:-options"]
         }
     }
     ```
   - 注意：`--release 21` 与 `-XDignore.symbol.file` 可以共存；但 `ParticlePlusClient` 用 `sun.misc.Unsafe` 注入枚举常量，需要在 Java 21 下重新验证（`--add-opens java.base/java.lang=ALL-UNNAMED` 之类）。

3. **Loom 版本升级**：`gradle.properties` 的 `loom_version=1.15.5` 需要抬到 `1.16.x`（Loom 1.15.5 是否支持 1.21.11 未验证；BBS 自身用 `1.15-SNAPSHOT`，但那是 BBS 自己的发布节奏，本项目用稳定版 1.16+ 更稳）。建议先在 `versions` 字典里加 `loom_version` 字段按版本隔离，避免影响 1.20.1/1.20.4 的现有构建。

4. **新增便捷任务**（仿 L230–233）：
   ```groovy
   registerVersionTask("build12111", "1.21.11", ["build"], "以 Minecraft 1.21.11 为目标构建。")
   registerVersionTask("runClient12111", "1.21.11", ["runClient"], "以 Minecraft 1.21.11 启动开发客户端（运行目录 run/1.21.11）。")
   ```

5. **Iris 仓库**：当前 `maven.modrinth:iris:...` 直接拉取。1.21.11 的 Iris 1.10.7 需要 Sodium 0.8.7，按 BBS `build.gradle` L88–89 的钉版方式加上 Sodium（仅 runClient 用，编译期可以不放）。

6. **BBS 自己用了 `splitEnvironmentSourceSets()`**：本项目作为 addon，**不强制要求** split source set，维持单 source set 即可。

### 2.3 `fabric.mod.json` 模板改动

`src/main/resources/fabric.mod.json` 中：

- `depends.minecraft` 当前 `${minecraft_version_range}` = `>=1.20.1 <=1.20.4`。
- 需要在 `gradle.properties` 把 `minecraft_version_range` 改成按版本分（或直接在 `processResources` 里按 `targetMc` 决定 expand 的值）。1.21.11 构建时应为 `~1.21.11`（与 BBS 自身一致）。
- `depends.java` 当前 `>=17 <22`。1.21.11 构建时应为 `>=21`。
- `depends.fabricloader` 当前 `>=0.15.0`。1.21.11 构建时建议 `>=0.19.3`。
- `depends.bbs` 当前 `>=2.7-0`，保留即可。

## 3. Mixin 配置改动

### 3.1 `compatibilityLevel` 必须升到 `JAVA_21`

8 个 mixins.json 当前全部是 `"compatibilityLevel": "JAVA_17"`：

| 文件 | 包 |
|---|---|
| `bbsplusplus.mixins.json` | `gbeic.bbsplusplus.mixin` |
| `bbsplusplus-irlite.mixins.json` | `...mixin.irlite` |
| `bbsplusplus-shadercurves.mixins.json` | `...mixin.shadercurves` |
| `bbsplusplus-vfx.mixins.json` | `...mixin.vfx` |
| `bbsplusplus-xavin.mixins.json` | `...mixin.xavin` |
| `bbspp-fslovecml.mixins.json` | `...mixin` |
| `bbspp-fslovecml.client.mixins.json` | `...mixin.client` |
| `bbspp-fslovecml.client.api.mixins.json` | `...mixin.client.accessor` |

> 这是"全局值"——同一个 jar 不可能同时带 `JAVA_17` 和 `JAVA_21` 两份。
> **决策点**：要么整个项目把 compatibilityLevel 抬到 `JAVA_21`（要求 1.20.1/1.20.4 构建也跑在 Java 21 上，Loom + Mixin 0.15+ 支持向后兼容，通常可行），要么拆出独立的 source set / 独立的 resources 目录按版本生成不同 mixins.json。**建议先试 `JAVA_21` 全量升级**，简单且 Mixin 官方推荐。

### 3.2 已确认失效的 Mixin（目标类在 1.21.11 BBS jar 中不存在）

## 4. 代码层破坏点（按严重程度）

### P0：MC 1.21.5 渲染管线大修（工作量主体）

1.21.5 起 Mojang 把 OpenGL 直接调用抽象成 `RenderPipeline` / `GpuDevice` / `RenderPass` / `RenderSetup` 体系。BBS 1.21.11 自己的 `bbs.accesswidener` 里有大段 `TODO(1.21.11 port)` 注释，列清了被移除的符号：

- `RenderSystem.shaderLightDirections` —— 移除
- `GlStateManager.TEXTURES` / `activeTexture` / `Texture2DState` —— 移除，改为 `GpuTexture`/sampler API
- `GlStateManager.CULL` / `CullFaceState` / `CapabilityTracker` —— 类移到 `com.mojang.blaze3d.opengl` 包，状态模型改了
- `BufferBuilder.buffer` / `elementOffset` / `vertexCount` / `grow(int)` —— accesswidener 项在 1.21.11 中**已被删除**（说明 BufferBuilder 内部结构变了）
- `Framebuffer` → 部分场景改 `OutputTarget`

本项目直接命中这些 API 的位置：

- **20 个文件**直接 `import com.mojang.blaze3d.systems.RenderSystem` 或调用 `GlStateManager.*`
- **32 个文件、184 处**涉及 `RenderSystem.*` / `BufferBuilder` / `Tessellator` / `VertexConsumerProvider` / `RenderLayer.*` / `Framebuffer`

|---|---|---|

**迁移参考**：`libs/bbs-fs-1.21.11/src/client/java/mchorse/bbs_mod/forms/renderers/` 下所有 FormRenderer 已经走在新渲染路径上，可直接对照 `ModelFormRenderer`、`BillboardFormRenderer`、`TrailFormRenderer` 学习新写法。BBS 1.21.11 新增了 `client/render/picker/`、`client/render/special/` 两个包，是新的渲染入口。

### P1：BBS 自身 API 变化

- `CubicVAORenderer` 被删除（见 §3.2）。
- `PlayerLikeEntity.PLAYER_MODE_CUSTOMIZATION_ID` 取代了旧 `PlayerEntity.PLAYER_MODEL_PARTS`（1.21.9 改名，BBS accesswidener 已加）。如果本项目有 mixin 针对玩家模型部件的，需要同步。
- `CustomCommandRenderer$Commands.customCommands` 新增访问加宽——本项目若有"手持物品重放"逻辑要复用。
- `RenderLayer.renderSetup` / `RenderSetup` 系列字段新增——本项目做 color grading / texture tween 的 Mixin（`CustomVertexConsumerTextureGradeMixin`、`BBSShadersTextureGradeMixin`、`FormRendererTextureGradeContextMixin`）大概率要改读这些新字段。

### P2：MC 1.20.5→1.21.x 其他破坏（按经验预判，未逐一验证）

- **物品组件系统（1.20.5 引入）**：`ItemStack.getTag()` → `get(DataComponentTypes.X)`，`NbtCompound` 读写方式变化。本项目 `KeyframeLocalizer`、`UIHotbarRenderer`、`HotbarClip`、`HotbarState`、`SprayedItem` 等涉及物品栏的位置需要复查。
- **网络包（1.20.5+ 用 PacketCodec）**：`network/BBSPlusPlusNetwork.java` 需要按新代码重写。
- **注册系统（1.21+ Registry 重构）**：`BBSPlusPlusBlocks` 等注册代码复查。
- **`Screen` / `DrawContext`（1.20.5 重写）**：本项目的 client screen 代码（`client/screen/` 下 `ColorGradeRenderer`、`TextureGradeRenderContext`、`VanillaParticleGradeContext`、`ModelTextureGradeShader`）需要对照新 DrawContext API 调整。
- **`Keyboard` / `Window`**：`KeyboardNarratorShortcutMixin`、`WindowClipboardMixin` 目标类仍在，但方法签名可能漂移。
- **`MinecraftClient` / `GameRenderer`**：`MinecraftClientMixin`、`GameRendererMixin`、`GameRendererAccessor` 的注入点要重对。

## 6. 建议执行顺序（暂不动手，仅作路线图）

1. **准备阶段（0.5 天）**
   - 确认本机/CI 已装 JDK 21（1.21.11 构建必须）。
   - 去 Modrinth 实拉 AAA Particles 1.21.11 最新 maven 坐标，填进 `gradle.properties`。

## 7. 未决问题 / 风险点

1. **Loom 版本**：当前 `1.15.5` 是否能直接解析 1.21.11，需要实测。若不行，需要在 `loom_version` 上做版本隔离（Loom 1.16+ 通常要求 Gradle 8.x）。
2. **Gradle 版本**：`gradle/wrapper/` 当前版本未确认，Loom 1.16 可能要求 Gradle 8.10+。
3. **`sun.misc.Unsafe` 注入枚举**：`ParticlePlusClient` 用 Unsafe 改枚举常量，Java 21 下模块封装更严，可能需要加 `--add-opens java.base/java.lang=ALL-UNNAMED`（参考 `build.gradle` L138–144 的注释）。
4. **Iris 1.10.7 与 Sodium 0.8.7 是绑定的**（BBS `build.gradle` L87–89 注释已说明），runClient 时必须同时装上，否则 Iris 启动崩溃。
5. **BBS 1.21.11 自己还在迁移中**（accesswidener 里大量 `TODO(1.21.11 port)`），意味着它的渲染 API 在后续小版本还会动；本项目重写时不要把 Mixin 注入点写得太死。
6. **`bbs.accesswidener` 是 BBS 自己声明的**，本项目作为 addon 不需要也不能再声明一份；本项目若需要新访问加宽，应该走 BBS 的 addon API 反馈，或在自己的 fabric.mod.json 里加 `accessWidener` 字段（但 Fabric 只允许每个 mod 一个 AW，需评估）。
