# 修复计划单：模型方块预览主页撤回撤销

## 一、问题描述

在 BBS FS 的**模型方块预览主页**（仪表板 → 模型方块面板，即 `UIModelBlockPanel`）中，按 `Ctrl+Z` / `Ctrl+Y` 没有任何反应，无法撤回或重做对模型方块的修改。

受影响的操作包括但不限于：
- 拖拽 Gizmo 移动/旋转/缩放模型
- 调整变换参数（位置/旋转/缩放）
- 切换形态（Form）
- 修改身体属性（碰撞箱、硬度、光照、声音等）
- 修改装备栏

---

## 二、根因分析

### 直接原因
`UIModelBlockPanel` **完全没有集成撤回撤销系统**，缺少三个核心部件：

| 缺失部件 | 作用 | 有此功能的参考类 |
|---|---|---|
| `UndoManager` | 维护撤销/重做栈 | `UIFormUndoHandler` 内部持有 |
| `UIUndoKeys` | 不可见覆盖层，捕获 `Ctrl+Z`/`Ctrl+Y` | `UIModelEditorPanel` 第 241 行 |
| `undo()` / `redo()` 方法 | 执行实际的状态回退/前进 | `UIModelEditorPanel` 第 786-801 行 |

### 数据流向
当前所有属性修改通过控件回调**直接写入** `ModelProperties` 对象，部分属性立即 `save()` 同步到服务端，**没有在修改前保存快照**，因此无法回退。

### 对比参考
模型编辑器（`UIModelEditorPanel`）有完整的撤回撤销：
- 使用 `UIFormUndoHandler` 基于值监听记录变更
- 使用 `ModelEditUndo` 做模型数据的快照式回退
- 通过 `UIUndoKeys` 捕获快捷键
- 支持历史面板跳转

---

## 三、修复方案

由于 BBS-Cubed 是 Addon，**不修改 BBS FS 源码**，通过 Mixin 注入实现。

### 步骤 1：新建快照式撤销记录类

**文件**：`src/main/java/gbeic/bbsplusplus/ui/model_blocks/ModelBlockEditUndo.java`

- 实现 `IUndo<ModelProperties>` 接口
- 保存修改前 / 修改后的 `MapType` 快照（通过 `ModelProperties.toData()` 获取）
- `undo()`：用修改前快照调用 `properties.fromData()` 恢复
- `redo()`：用修改后快照恢复
- 支持连续操作合并（同类型拖拽合并为一条记录）

### 步骤 2：新建 Mixin 注入撤回撤销能力

**文件**：`src/main/java/gbeic/bbsplusplus/mixin/client/UIModelBlockPanelUndoMixin.java`

注入到 `UIModelBlockPanel`，添加以下能力：

#### 2.1 添加字段
- `UndoManager<ModelProperties> bbspp$undoManager` — 撤销栈
- `MapType bbspp$lastSnapshot` — 上一次快照，用于对比变化
- `boolean bbspp$isUndoing` — 防止 undo/redo 过程中触发新记录

#### 2.2 注册快捷键
在面板构造完成后（`@Inject` 到构造方法末尾或 `fill` 首次调用时）：
```java
this.add(new UIUndoKeys(this::bbspp$undo, this::bbspp$redo).full(this));
```

#### 2.3 实现 undo / redo
```
undo():
  1. 从 undoManager 弹出上一条记录
  2. 用 before 快照恢复 ModelProperties
  3. 重新 fill UI 控件（调用 fill(modelBlock, false)）
  4. save 到服务端（同步方块数据）

redo():
  类似，用 after 快照恢复
```

#### 2.4 捕获修改并记录快照
需要在以下时机记录"修改前快照"并在修改完成后推入撤销栈：

| 修改方式 | 捕获时机 |
|---|---|
| Gizmo 拖拽 | `subMouseReleased` — 拖拽开始时快照，释放时对比并推入 |
| `UIPropTransform` 参数 | 控件回调包装 — 首次修改时快照，失焦/延迟后推入 |
| `UITrackpad` / `UIToggle` 等 | 同上，包装回调或在 `fill` 后统一处理 |
| 形态切换 / 装备修改 | 对应控件回调 |

**简化策略**：在 `fill()` 加载方块时保存基线快照；在 `mouseReleased`（gizmo结束）和控件值变化回调中，对比当前状态与基线，若不同则推入 undo 栈并更新基线。连续拖动通过时间窗口合并。

### 步骤 3：注册 Mixin

**文件**：`src/main/resources/bbsplusplus.mixins.json`

在 `client` 数组中添加：
```json
"client.UIModelBlockPanelUndoMixin"
```

## 四、关键技术点

1. **快照恢复后必须重新 fill UI**：`fromData()` 只恢复数据对象，UI 控件的显示值不会自动更新，需要调用 `fill()` 刷新。
2. **undo 后必须 save 到服务端**：模型方块数据存储在方块实体中，本地恢复后需要通过 `ClientNetwork.sendModelBlockForm()` 同步，否则关闭面板后会被服务端数据覆盖。
3. **防止循环触发**：undo/redo 恢复数据时会触发控件回调，需要 `isUndoing` 标志位跳过快照记录。
4. **连续操作合并**：拖动 trackpad 或 gizmo 时会产生大量连续修改，应通过时间窗口（如 500ms 无新修改）合并为一条撤销记录，参考 `UIFormUndoHandler` 的 `BATCH_TIMEOUT` 机制。

## 六、验证方法

1. 进入游戏，放置模型方块，打开仪表板 → 模型方块面板
2. 用 Gizmo 移动模型 → 按 `Ctrl+Z` → 模型应回到原位 → 按 `Ctrl+Y` → 模型应回到移动后位置
3. 调整变换参数（如旋转 Y 值）→ `Ctrl+Z` 回退 → `Ctrl+Y` 重做
4. 切换形态 → `Ctrl+Z` 回退
5. 修改身体/装备属性 → `Ctrl+Z` 回退
6. 连续拖动参数后 `Ctrl+Z`，应一次回退整个拖动操作而非逐帧回退
7. 关闭面板后重新打开，确认 undo 后的数据已正确保存到方块
8. 确认不影响模型编辑器（`UIModelEditorPanel`）原有的撤回撤销功能

## 七、风险与注意事项

- **Mixin 注入点**：`UIModelBlockPanel` 的 `fill()` 方法是私有的，需要用 `@Inject` 精确匹配方法描述符，避免注入失败。
- **快照体积**：`ModelProperties` 包含形态数据，快照可能较大，但模型方块数据量通常很小，无性能问题。
- **与现有 Mixin 兼容**：项目中已有 `UIModelBlockPanelGizmoThrottleMixin`，新 Mixin 不应与之冲突（一个管渲染节流，一个管撤销，互不干扰）。
- **枪械模型方块**：`GunProperties extends ModelProperties`，快照方案天然兼容，无需特殊处理。
