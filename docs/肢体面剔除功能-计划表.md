# 肢体面剔除（Limb Culling）功能实施计划表

> 状态：**仅规划，暂不改动代码**。本计划基于当前依赖 **BBS 2.7（`libs/archive/bbs-2.7/bbs-2.7-1.20.4.jar`）** 的反编译结果。
> 目标：在模型编辑器 → 配置页 → 顶部 Tab 栏的「姿势」之后，新增一个「肢体面剔除」页签，可逐肢体（骨骼）单独开启背面剔除。

---

## 一、功能需求

1. 模型编辑器的「配置页」顶部 Tab 栏，目前顺序为：
   `常规 / 骨骼 / 焊接 / 盔甲 / 物品 / 第一人称 / 程序化 / 姿势`
2. 在 **「姿势」之后**追加第 9 个 Tab：**「肢体面剔除」**。
3. 页面布局**复用「骨骼」页（骨骼可见性）**：
   - 顶部：骨骼搜索框；
   - 中部：骨骼列表（树形）；
   - 下方：选中骨骼的详情面板。
4. 详情面板**只保留一个开关（toggle）**，功能为「为该肢体开启面剔除」。
5. **删除**「骨骼」详情面板中另外两行：
   - **镜像骨骼**（`MODEL_EDITOR_BONE_MIRROR` → `flippedParts`）；
   - **选取覆盖**（`MODEL_EDITOR_BONE_PICKING` → `pickingOverrides`）。
   - 注意：这两行只在**新页面**中不复用；原「骨骼」页保持原样、不动。
6. 数据需持久化到模型的 `config.json`，与模型一起保存。

## 二、现状与关键代码（已核实）

### 2.1 配置页 UI

| 角色 | 类（`mchorse.bbs_mod.*`） | 说明 |
|---|---|---|
| 配置页主体 | `ui.model_editor.UIModelConfigEditor` | 持有 `tabs`、`pages[]`、`sections[]` 及各页面控件 |
| 顶部 Tab 枚举 | `ui.model_editor.UIModelConfigEditor$Tab` | 常量：`GENERAL,BONES,WELDS,ARMOR,ITEMS,FIRST_PERSON,PROCEDURAL,POSES`；字段 `icon`、`label` |
| Tab 条 | `ui.framework.elements.utils.UITabStrip` | 由 `UIModelConfigEditor$1` 继承，重写 `pressTab(int,UIContext)` |
| 骨骼列表 | `ui.model_editor.UIModelBoneList` | 构造 `(Consumer<String>, Supplier<String>, Runnable)` |
| 骨骼详情 | `UIModelConfigEditor.bonePanel`（`UIElement`） | 由 `fillBone()` 填充 |
| 面板宿主 | `ui.model_editor.UIModelEditorPanel` | `refreshPreview()` 等 |

关键方法（`UIModelConfigEditor`）：

- `createTabs()`：遍历 `TABS`，为每个 Tab 建一个 `UIIcon`（20×20）并 `tabs.addTab(...)`；再为每个 Tab 建一个 `UIScrollView` 存入 `pages[tab.ordinal()]` 并 `add(...)`。
- `createPages()`：硬编码填充每个页面内容（常规各 section、骨骼页、焊接页、姿势页）。
- `pressTab(int)`（`UIModelConfigEditor$1`）：`openTab(TABS[index])`，返回 true。
- `openTab(Tab)`：特殊处理（如 `PROCEDURAL` 调 `fillProcedural()`）后 `showPage(tab)` + `modelPanel.refreshPreview()`。
- `showPage(Tab)`：遍历 `TABS`，`page(t).setVisible(t == selected)`，并写入静态字段 `lastTab`。
- `page(Tab)` = `pages[tab.ordinal()]`。
- `fillBone()`：`bonePanel` 中依次放三行（见下）。
- `fillBones()`：刷新骨骼列表并保留当前选中，再 `fillBone()`。

`fillBone()` 三行（**新页要复用第 1 行、去掉第 2、3 行**）：

1. `UIToggle`，标签 `UIKeys.MODEL_EDITOR_BONE_VISIBLE`，初值 `!config.disabledBones.contains(bone)`，回调增删 `disabledBones`。
2. `UI.labelRow(MODEL_EDITOR_BONE_MIRROR, bonePicker(...))` —— 镜像骨骼，读 `mirrorOf`、写 `setMirror`（`flippedParts`）。
3. `UI.labelRow(MODEL_EDITOR_BONE_PICKING, bonePicker(...))` —— 选取覆盖，读 `pickingOverrides.containsKey`、写 `setPickingOverride`（`pickingOverrides`）。

### 2.2 数据模型

| 角色 | 类 / 字段 | 说明 |
|---|---|---|
| 模型配置 | `cubic.model.config.ModelConfig`（extends `ValueGroup`） | 全部字段为 `Value*`，构造函数中 `add(value)` 注册 |
| 模型级面剔除 | `ModelConfig.culling`（`ValueBoolean`） | config.json 中 `"culling"`，控制整个模型是否背面剔除 |
| 骨骼可见集合 | `ModelConfig.disabledBones`（`ValueStringKeys`） | **新字段的直接参照样板** |
| 镜像 / 选取 | `flippedParts`、`pickingOverrides`（`ValueStringMap`） | 新页不使用 |

- `ValueGroup.add(BaseValue)` 为 `public`，可在构造函数 TAIL 动态注册新字段。
- `ModelConfig.canPersist(...)` 对个别字段做条件持久化，**默认分支调用 `super.canPersist`（返回 true）**，因此新字段会正常写入 `config.json`。
- `ValueStringKeys` 构造：`(String key)`，值为 `Set<String>`，序列化/反序列化由基类完成。

### 2.3 渲染链路（面剔除生效点）

面剔除是全局渲染状态（`RenderSystem.enableCull/disableCull`），三处涉及 `isCulling`：

| 类 | 位置 | 行为 |
|---|---|---|
| `cubic.ModelInstance` | `isCulling()` | 返回 `config.culling.get()`；`getDisabledBones()` 返回 `disabledBones` 集合 |
| `forms.renderers.ModelFormRenderer` | `renderModel(...)` 开头 | 整个模型渲染前：`if (!model.isCulling()) RenderSystem.disableCull()` —— 设定模型级基础状态 |
| `cubic.render.CubicVAORenderer`（extends `CubicCubeRenderer`） | `renderGroup(...)` | 每骨骼（group）按**材质级**覆盖再切换 culling（见下） |

`CubicVAORenderer.renderGroup` 中 culling 逻辑（核心注入点）：

- `materialCulling = FormMaterialLevels.materialCulling(modelForm, material)` —— 材质级：`0` 跟随、`1` 强制开、其它强制关；
- `base = model.isCulling()` —— 模型级；
- 目标 = `materialCulling != 0 ? (materialCulling==1) : base`；
- 若目标与当前不一致 → 渲染前 `enableCull/disableCull`，渲染后恢复；
- 透明物体不立即绘制，而是加入 `FormTranslucentQueue`，`ModelVAOCommand` 构造时把 `model.isCulling()` 作为布尔参数捕获（延迟绘制时使用）。

**三级优先级（目标设计）**：`材质级 > 肢体级(新) > 模型级`。

## 三、总体设计

### 3.1 数据层：新增一个肢体集合字段

在 `ModelConfig` 中以 Mixin 外挂一个字段：

- 类型：`ValueStringKeys`
- 建议键名：`limbCullingBones`（语义：**集合中的肢体 → 强制开启背面剔除**）
- 空集合 = 全部肢体跟随模型级 `culling`，与现版本行为完全一致（默认无副作用）。

### 3.2 渲染层：让肢体级覆盖参与每个 group 的 culling

在 `CubicVAORenderer.renderGroup` 中，把读取 `model.isCulling()` 的地方替换为「肢体级覆盖后的基础值」：

```
base = limbCullingBones.contains(group.id) ? true : model.isCulling();
```

之后材质级仍可覆盖（材质优先级最高），透明队列命令捕获的布尔值也随之正确（因为拦截的是同一个 `isCulling()` 调用）。

### 3.3 UI 层：新增第 9 个 Tab 与页面

由于 `Tab` 是枚举、`pages[]` 长度固定，采用**「手动追加 + 少量注入」**方案（比枚举扩展更可控，见 §六）：

- `createTabs()` TAIL：向 `tabs` 手动 `addTab(新图标 UIIcon)`，并新建一个 `UIScrollView` 作为新页面、`add(...)` 到容器，引用存入 Mixin 唯一字段。
- 拦截 `pressTab(index)`：当 `index == 8`（新 Tab）时调用自定义 `openLimbCulling()`；否则走原逻辑。
- `showPage(Tab)` TAIL：切到原版页时，把新页面 `setVisible(false)`。
- `openLimbCulling()`：隐藏原版 8 页 / 显示新页，触发 `fillLimbCullingBones()` 与 `refreshPreview()`。
- 新页面内容：`UISearchList` + `UIModelBoneList`（独立实例）+ 详情面板；详情面板仅一个 toggle，绑定新字段 `limbCullingBones`。

   - `@Unique public ValueStringKeys bbspp$limbCullingBones;`

     - `this.bbspp$limbCullingBones = new ValueStringKeys("limbCullingBones");`
     - `((ModelConfig)(Object)this).add(this.bbspp$limbCullingBones);`
   - （可选）提供一个 duck 接口 `LimbCullingConfigHolder` 暴露 getter，便于其它类访问。

3. 验证：进游戏打开任意模型 config.json，应出现空的 `"limbCullingBones": []`；手动填一个骨骼名后重载能读回。

> 注意重命名：`ModelConfig.renameBone(...)` 负责骨骼改名时联动各集合。新字段是「骨骼集合」，建议在改名逻辑里同步处理（可在 `renameBone` 注入，或确认 `ValueStringKeys` 是否被现有重命名流程覆盖；若不覆盖则自行替换集合中的旧名）。

### 阶段 B — 渲染层

4. 新建 `mixin/LimbCullingVAORendererMixin.java`

## 六、关键技术取舍：为什么用「手动追加 Tab」

`Tab` 是枚举，`pages[]` 长度在构造时按 `TABS.length` 固定。直接扩展枚举虽可让 `pressTab/showPage/page/cycleTab` 自动适配，但需要构造私有枚举常量、改写 `$VALUES`，样板脆弱、对加载顺序敏感。

「手动追加」只需 4 处注入（`createTabs` 追加图标+页面、`pressTab` 拦截新索引、`showPage` TAIL 隐藏新页、自定义 open），每处都是普通 UI 操作，**不依赖枚举黑科技**，且与项目现有 `UIModelPoseEditorAccessor`、`UISectionMixin` 等 Accessor/注入风格一致。若后续团队更倾向枚举扩展，可在评审后替换，两者数据层与渲染层完全相同。

## 七、风险与注意事项

1. **透明渲染队列**：`FormTranslucentQueue` 的 `ModelVAOCommand/VertexBufferCommand/BOBJCommand` 会在构造时捕获 culling 布尔。必须确保拦截覆盖这些构造点，否则半透明肢体的肢体级剔除失效。
2. **CPU / 焊接路径**：`CubicCubeRenderer` 不逐 group 切换 culling；焊接模型多骨骼共几何体，无法逐肢体剔除 —— 明确为限制并在 UI 上提示（或对焊接肢体禁用该开关）。
3. **骨骼重命名**：新增集合需在 `renameBone` 时同步，否则会残留无效 id。
4. **默认值无副作用**：空集合时必须与现版本逐像素一致，避免影响已有模型。
5. **Tab 激活高亮**：手动追加后需确认 `UITabStrip` 的 active index（=8）能正确高亮新图标；`lastTab` 为静态枚举、无法表示新页，需用 `@Unique` 布尔标记新页激活状态，避免与 `cycleTab`、快捷键（如 Ctrl+Tab）冲突。
6. **`remap` 标记**：BBS 类不参与 Minecraft 官方重映射，按现有同类 Mixin 的 `remap` 约定填写（参考 `CubicCubeRendererMixin` 用 `targets` + `remap=true`，`ModelGroupMixin` 用 `remap=false`）。

## 九、建议落地顺序

1. 先做 **阶段 A（数据层）** 并验证持久化 —— 风险最低、是后续基础。
2. 再做 **阶段 B（渲染层）**，用临时写 config.json 的方式验证逐肢体剔除与优先级（此时还没有 UI）。
3. 最后做 **阶段 C + D（UI 与语言）**，把渲染层对接到可视化开关。
4. 每阶段独立编译（`./gradlew compileJava` / `build`）并按 §八 对应项回归，再进入下一阶段。
